## 1. 文件命名

```
code/dayNN_topic.py
```

| 规则 | 说明 | 正例 | 反例 |
|---|---|---|---|
| 两位编号 | `day01` … `day24`，不足两位补 0 | `day01_first_python.py` | `day1_第一.py` |
| 全 ASCII | 只用 `a-z 0-9 _`，**禁止中文与空格** | `day07_kmer_token.py` | `day07_k-mer切分.py` |
| 小写 | 全部小写 | `day12_esm_embedding.py` | `day12_ESM_Embedding.py` |
| 下划线分词 | 主题用下划线连接 | `day18_random_forest.py` | `day18-randomForest.py` |
| 主题 ≤3 个词 | 文件名即索引，别写句子 | `day03_csv_filter.py` | `day03_如何读取csv并筛选耐药菌株.py` |
| **文章与脚本同名前缀** | `articles/dayNN_topic.md` 与 `code/dayNN_topic.py` 的 `dayNN_topic` 部分**必须逐字符一致**，读者按文章标题找脚本才不会迷路 | `day01_first_python.md` + `day01_first_python.py` | `day01_from_ast_to_first_python.md` + `day01_first_python.py` |

> 为什么禁中文/空格：Windows 的 cmd/PowerShell、Linux 的 shell、Git 在含空格与中文的路径上都各有各的坑；ASCII 命名是全球通用解。

## 2. 文件头模板（**每个脚本必须原样带上，只改内容**）

```python
# ============================================================
# amr-ai-lab / Day NN — 当日主题（中文，一句话）
# ------------------------------------------------------------
# 对应文章：articles/dayNN-topic.md      ⏰ 文件名以 articles/ 下最终命名为准；文章与脚本主题词必须一致（见第 1 节）
# 一句话作用：这个脚本跑完，读者手上多了一个什么看得见的东西
# 运行命令：conda activate amr_ai && python code/dayNN_topic.py
# 预期输出：终端打印什么 + outputs/ 下多出哪个文件
# 依赖：python 3.11+ / pandas 2.2.2 / matplotlib 3.8.4（见根目录 requirements.txt）
# 作者备注：这个类比想说明什么 —— 用一句实验室或移动端开发的话，
#           讲清这个脚本在认知地图上的位置，以及它**不**演示什么。
# ============================================================
```

字段填写要求：

- **对应文章**：必须能在 `articles/` 里找到同名文件，找不到就是断链，要修
- **一句话作用**：写给「半年后的自己」，用动词开头（读出/算出/画出/对比出）
- **运行命令**：必须可直接复制，且在项目根目录执行
- **预期输出**：写具体文件名，别写「会出图」
- **作者备注**：这是本包最有价值的字段。要回答「这个类比想说明什么」+「这个脚本没演示什么」

## 3. 注释语言与中文/ASCII 规则

| 位置 | 用什么 | 原因 |
|---|---|---|
| 注释（`#` 后面） | **中文** | 读者是中文母语，注释是给人看的 |
| 终端打印（`print`） | 中文优先 | 即时反馈要看得懂 |
| 图表的标题/轴标签/图例 | **英文** | matplotlib 默认字体不含中文字形，中文会渲染成「□□□」方块；不折腾字体的唯一稳解是图上用英文 |
| 特殊字符 | **ASCII 替代** | `µg/mL` → `ug/mL`；`≥` → `>=`；`α` → `alpha`。同样是字体与编码的保险 |
| 文件编码 | UTF-8（Python 3 默认） | 不要加 encoding 声明，除非读外部 csv 时对方是 GBK |

示例代码：

```python
plt.ylabel("MIC (ug/mL, log scale)")     # 图上用英文 + ASCII 单位，避免"方块字"和编码事故
# 这一行是在把 MIC 换算成对数轴，因为 0.25 到 32 跨了两个数量级
```

## 5. 路径与输出（**图默认存 outputs/**）

**禁止**写死绝对路径（`/Users/xxx/...`、`C:\xxx\...`）——别人 clone 下来就跑不了。

统一写法：

```python
from pathlib import Path
OUTPUT_DIR = Path(__file__).resolve().parent.parent / "outputs"   # 相对脚本自身定位，任何目录都能直接跑
OUTPUT_DIR.mkdir(parents=True, exist_ok=True)                     # 目录不存在就建
...
plt.savefig(OUTPUT_DIR / "dayNN_主题.png", dpi=150)                # dpi=150：屏幕看清 + 推文够用
```

命名：`outputs/dayNN_主题.png`（与脚本同名前缀，反查方便）。

> 这个小动作解决了一大类「在我电脑上能跑」事故：读者在 `code/` 里跑、在项目根跑、在 VS Code 里点运行，结果都一致。

## 12. 发布前三查/三审清单（文章可发布性闸门）

> 本清单是「文章能否发布」的最终闸门，独立于第 11 节的「代码提交前自查」。任一 **【可发布性 P0】** 命中即视为**不可发布**，必须退回修改后才能上线。

### 【可发布性 P0】文风红线：禁止第一人称自传

- **文章主角须为中性「检验科研人」角色**：全程以第三人称 / 第二人称叙述（"检验科研人""你""我们"），不把作者个人履历当主线串联全文。
- **禁止第一人称自传**：不得出现「我写了 X 年 App」「我当年在某某实验室……」「我做了 N 年生信」等以作者本人经历为线索开篇或串联的内容。
- **个人背景仅可放文末作者注**：若需要交代作者资历，统一放在文章末尾「作者注」区块；正文（含开头与各段落）一律不得出现第一人称自传。
- **命中即不可发布**：出现第一人称自传 → 直接打回，不再计其他项。

### 【可发布性 P0】技术一致性（与 code/ 同名脚本联动）

- 折点 / 数值 / 颜色 / 示例输出必须与 `code/` 下**同名前缀脚本**逐字符一致（如妥布霉素 `BREAKPOINTS["tobramycin"] = (1, 2)`）；不一致即不可发布。
- 所有模型名 / 数据库名 / 版本号必须带 ⏰ 标记且锁版本；出现「pip install 最新版」或裸版本号即不可发布。
